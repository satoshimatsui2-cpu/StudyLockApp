# 発音チャレンジ 3単語セッション不具合の修正プラン

発音チャレンジが2単語で終了してしまう不具合を調査・修正します。セッション開始時のインデックス初期化漏れ、単語選出時の重複、および遷移ロジックの不整合を解消します。

## ユーザーレビューが必要な事項
- 特になし。仕様に基づいた修正となります。

## 提案される変更点

### 1. データ管理 (AppSettings.kt)
- `activePronunciationChallengeIds` の取得時に、件数(3件)に加えて **重複がないこと (distinct)** をチェックするよう強化します。
- `clearPronunciationChallenge()` で、セッションステータス、インデックス、失敗IDに加えて、アクティブIDリストも確実に削除します。

### 2. 単語選出ロジック (ChallengeRepository.kt)
- 選出結果に `distinctBy { it.no }` を適用し、IDの重複を確実に排除します。
- 重複排除後も3語に満たない場合は、空リストを返してセッション開始を阻止します。

### 3. セッション開始ロジック (SkillChallengeViewModel.kt)
- 新規セッション開始時 (`confirmStartPronunciation`) に、`pronChallengeIndex = 0` を確実にセットします。
- 単語不足時のメッセージを「発音チャレンジに必要な単語が足りません」に統一します。
- ログ出力を強化し、選出されたID、件数、開始/再開の区別などを記録します。

### 4. 画面遷移ロジック (PronunciationChallengeActivity.kt)
- `onCreate` 時のログ出力を強化し、`currentIndex` と `words` の整合性を確認します。
- `btnNextWord` の遷移条件を `if (currentIndex < words.lastIndex)` に統一し、0 -> 1 -> 2 の遷移を保証します。
- 3語目でのみ `handleSessionEnd()` が呼ばれるようにします。

## 検証プラン

### 自動テスト
- `ChallengeRepositoryTest.kt` に以下のケースを追加：
  - 新規セッションがインデックス 0 から始まること。
  - 再開セッションが保存されたインデックスから始まること。
  - 選出される ID がすべて異なること。
  - 候補不足時に空リストが返ること。

### 手動確認
1. セッションを開始し、「1 / 3」「2 / 3」「3 / 3」と正しく表示され、3語回答できることを確認。
2. セッションを途中で終了し、再開した際に正しい単語から始まることを確認。
3. セッション終了後、新規に開始した際に再び「1 / 3」から始まることを確認。
